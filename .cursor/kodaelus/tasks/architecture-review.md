# Architecture Improvement Review

## Architecture Improvement Review

Use this when the user asks for improvements, alternatives, review, or "what would you do differently" without asking to implement yet.

For each decision point:

1. **Decision.** What must be chosen.
2. **Options.** 2 - 4 approaches grounded in this codebase.
3. **Recommendation.** One choice.
4. **Why.** Boundaries, coupling, testability, operational cost, migration risk.
5. **Rating 1 - 5.** 5 strong fit; 4 good with minor tradeoffs; 3 viable with meaningful tradeoffs; 2 misaligned; 1 avoid.
6. **Confidence: NN% | Evidence:** one-line rationale.

Tie options to files read. Put tactical nits in a short Minor subsection without ratings. A quick answer still includes one rated fork when a real fork exists.
